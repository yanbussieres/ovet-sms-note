Who owns minting, sending, scheduling, and overuse

Clerk cannot own the login-handle ceilings of 5/min per code and 600/min global because guesses and spent handles return null before Clerk is called. Ovet owns clinic policy and any traffic a vendor never sees. Clerk and Telnyx own remaining capacity on the calls they actually receive. Convex is the clock and the bucket runtime — it does not choose the numbers.

Ovet / Convex app

Policy and unseen traffic

  • Consent, reservation, clinic window
  • Handle issue / claim / release
  • Guessing bounds 5 and 600
  • Ten-attempt budget, follow-up tasks

Clerk

Identity, not SMS

  • Parent account find/create at send
  • Sign-in token only after a valid claim
  • BAPI 100/10s dev, 1000/10s prod
  • FAPI sign-in 5/10s after the ticket exists

Telnyx

Wire and carrier

  • Accept one send; sent means acceptance
  • Long code ~0.1 msg/s; queue then 40318
  • Optional daily spend → 429 + 40333
  • STOP is provider withdrawal, not Ovet consent

Convex runtime

When work runs

  • scheduler.runAt invitations / reminders
  • Workpool: booking SMS + expiry
  • Rate limiter: local buckets
  • Built-in crons: purge / sweep, not 18:00

1. Two processes, two limit planes

Minting a ticket and sending an SMS share a visit, but they are limited by different owners. Mixing them produces coincident numbers (Convex 600 vs Clerk 600/min) that look aligned and are not.

2. Why Clerk cannot own 5 / 600

loginCodes.redeem is public and unauthenticated. claim takes a Convex rate-limiter token, then looks up the handle. Only a live, unclaimed, unexpired row continues to parentSignInToken.

        Clerk-->>Phone: 120s ticket

Clerk rate limits apply only to requests Clerk receives. A guessing campaign, a double-open of a spent handle, and an expired handle are Ovet database events. Waiting for Clerk 429 on those paths waits forever. Clerk FAPI “5 sign-in creations / 10s” is also the wrong layer: it runs after a ticket already exists, on the Parent app, not on handle guesses.

3. What Ovet should own

Guessing a handle Per-code and global Convex buckets; claim-before-lookup Nothing — Clerk is not called Ovet. 5 is a retry ceiling for one SMS. 600 is a deployment-wide unauthenticated redeem ceiling. Do not copy Clerk’s table.
Successful mint 120s ticket, single-use handle, release on Clerk failure Clerk BAPI remaining + Retry-After Ovet owns ticket lifetime. Clerk owns whether this mint is accepted. Classify Clerk 429 like Telnyx; do not let it look like “expired”.

When to send 18:00 invitation, 07:00–21:00 window, imminent < 6h, contact cutoff Neither Clerk nor Telnyx scheduled-send Ovet / clinic settings. Convex runAt fires that instant. Crons do not own 18:00.
Retry after a bad send Max 10 attempts, jittered backoff, clinic task when unknown Telnyx Retry-After, 40333 spend, queue Ovet owns the budget. Telnyx delay is a floor inside that budget, capped at 1 hour in telnyx.ts.
Consent / STOP Visit grant, permission generation, withdrawal pages Provider STOP/START on the sender Ovet consent is never restored by Telnyx START. Two different permissions.
Spend / flood Reservation + org invitation bucket + ten-attempt cap Profile daily_spend_limit if enabled (not live-read here) Ops may set a Telnyx dollar cap. That is a fuse, not clinic policy.

4. How to align the numbers

Do

  • Keep a local Convex bound on every unauthenticated entry (redeem, withdrawal).
  • Treat vendor 429 + Retry-After as remaining capacity on that call.
  • Size staff send rate for one long code (~1 SMS / 10s default) when many invitations share 18:00.
  • Release an unexpired handle if Clerk mint fails, and tell the parent to retry — not that the link expired.
  • Leave 5 as a product guess cap even if Clerk later returns 429 on real mints.

Do not

  • Set Convex 600 because Clerk dev BAPI is 100/10s.
  • Set Convex 5 because Clerk FAPI sign-in creation is 5/10s.
  • Delete local buckets and “just handle Clerk errors”.
  • Use Telnyx scheduled messages or a second queue for clinic 18:00.
  • Auto-loop redeem on 429 (burns the handle and the bucket).
  • Let Workpool parallelism 8 imply 8 SMS/s — Telnyx will queue or 429.

Suggested split: Ovet invents bounds for traffic vendors never see; Ovet stays conservatively under documented vendor capacity for traffic they do see; vendors remain the last word via 429. The 5 and 600 stay Ovet numbers. They can be revised from abuse evidence, not from Clerk’s marketing table.

5. Convex primitives on this process

Rate limiter component Token buckets in Convex Yes — this is how Ovet owns 5/600 and the other unauthenticated / staff flood gates.

6. Burst at 18:00 vs provider throughput

Many invitations can be scheduled for the same clinic-local 18:00:00.000. Convex will wake them together. Telnyx’s default long-code send rate is 0.1 messages per second per number (~6/min). Extra requests queue for up to four hours, then 40318. That is a send-plane limit. It does not protect redeem. Workpool maxParallelism: 8 is a Convex execution cap for booking jobs, not an SMS MPS setting.
